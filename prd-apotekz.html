1. Ringkasan Eksekutif

ApotekZ adalah sistem manajemen apotek berbasis web yang dirancang untuk mengotomatisasi dan mengintegrasikan seluruh operasional apotek modern di Indonesia. Sistem ini mencakup transaksi penjualan (POS), manajemen inventori obat, pencatatan resep dokter, shift kasir dengan rekonsiliasi kas, purchase order ke pemasok, stok opname dengan audit trail, tracking batch/lot untuk recall BPOM, serta analitik cerdas berbasis AI untuk prediksi permintaan dan laporan keuangan.

Masalah yang Diselesaikan

  • Operasional manual yang lambat: Kasir menggunakan kalkulator dan catatan manual, rawan kesalahan hitung.
  • Tidak ada pelacakan resep: Resep dokter tidak tercatat dengan baik, sulit dilacak ulang jika ada recall atau komplain.
  • Stok tidak terkontrol: Tidak ada peringatan stok menipis atau obat kadaluarsa, sering kehabisan tanpa diketahui.
  • Kasir tidak akuntabel: Tidak ada sistem shift, sehingga selisih kas sulit ditelusuri ke kasir mana.
  • Tidak ada tracking batch: Jika BPOM mengeluarkan surat recall, tidak tahu batch mana yang harus ditarik.
  • Laporan keuangan manual: Pemilik kesulitan melihat profit/loss real-time, harus rekap manual dari struk.

Solusi ApotekZ

ApotekZ menggabungkan 14 modul fungsional dalam satu aplikasi web yang dapat diakses dari browser apapun. Sistem ini menggunakan Supabase (PostgreSQL) sebagai database terpusat, Next.js sebagai framework frontend, dan terintegrasi dengan layanan AI (Groq, OpenRouter, OpenAI) untuk analitik prediktif.

Halaman utama untuk Owner dan Apoteker. Menampilkan ringkasan operasional apotek secara real-time.

Komponen yang Ditampilkan

  • Stat cards: Total omzet hari ini, jumlah transaksi, total obat terjual, stok kritis

6. Modul Kasir / Point of Sale (POS)

Modul inti untuk transaksi penjualan. Dapat diakses oleh Owner, Apoteker, dan Kasir.

Fitur Utama

  • Pencarian obat: Cari berdasarkan nama, kode, atau barcode. Real-time saat mengetik.
  • Keranjang belanja: Tambah/hapus item, ubah quantity, hitung subtotal otomatis.
  • Multiple payment methods: Cash, Debit, QRIS, Transfer.
  • Diskon & PPN: Diskon dalam Rupiah atau persen, PPN 11% dapat di-toggle.
  • Customer lookup: Pilih pelanggan terdaftar untuk poin loyalty, atau input walk-in customer.
  • Cetak struk: Thermal printer 80mm dengan logo apotek, alamat, SIKL, dan footer ucapan terima kasih.
  • Cetak invoice A4: Invoice formal untuk arsip internal dengan NPWP.
  • Auto-generate invoice number: Format INV-YYYYMMDD-HHMMSS###

9. Modul Purchase Order ke Pemasok

Modul untuk mengelola pembelian obat dari supplier/pemasok. Mengganti "supplier" yang sebelumnya hanya text field di obat, menjadi alur pembelian yang terstruktur.

Fitur

  • Master data supplier: CRUD supplier dengan nama, contact person, telepon, email, alamat, catatan.
  • Buat Purchase Order: Pilih supplier, tambah item obat dengan quantity dan unit cost, sistem hitung total cost otomatis.

  • Auto-update stok: Saat PO diterima, stok medicine bertambah sesuai received quantity.
  • Auto-generate PO number: Format PO-YYYYMMDD-###
  • Cetak PO: Cetak dokumen PO untuk dikirim ke supplier.

10. Modul Shift Kasir & Rekonsiliasi

Modul untuk akuntabilitas kasir. Setiap kasir membuka shift dengan modal awal, semua transaksi masuk ke sesi tersebut, dan tutup shift dengan rekonsiliasi kas.

Catatan workflow: Jam buka dan tutup shift dapat diinput manual (datetime picker) — tidak otomatis tercatat saat klik tombol. Ini karena di real life, saat banyak aktivitas pelayanan, kasir baru sempat input setelah pergantian shift selesai.

Fitur

  • Buka shift: Input jam mulai shift (bisa mundur) + modal awal kas tunai.
  • Auto-generate session number: Format S-YYYYMMDD-###
  • Shift aktif banner: Tampil di atas, menunjukkan shift aktif, operator, jam buka, modal.
  • Hanya 1 shift aktif: Tidak bisa buka shift baru jika masih ada yang aktif.
  • Tutup shift: Input jam selesai shift + hitung fisik uang di laci. Sistem hitung expected cash (modal + penjualan cash) dan selisih.
  • Selisih kas: Lebih (surplus), kurang (defisit), atau balance (sempurna) — dengan kode warna.
  • Cetak laporan shift: Laporan lengkap dengan semua transaksi, breakdown cash vs non-cash, dan selisih.
  • Catatan shift: Bisa tambah catatan saat tutup shift untuk dokumentasi.

12. Modul Stok Opname

Modul untuk hitung stok fisik vs sistem, catat selisih, dan adjust stok dengan audit trail. Wajib untuk audit farmasi.

Fitur

  • Mulai sesi opname: Sistem otomatis snapshot stok semua obat saat sesi dibuat (system_stock).
  • Input hasil hitung fisik: Per obat, input jumlah fisik yang dihitung. Sistem hitung selisih real-time.
  • Search cepat: Cari obat untuk input cepat kalau stok banyak.
  • Status sesi: draft → completed. Setelah completed, tidak bisa diubah.
  • Auto-adjust stok: Saat sesi diselesaikan, stok sistem auto-update sesuai hasil fisik. Setiap item ditandai adjusted: true.
  • Audit trail: Setiap item mencatat system_stock, physical_stock, difference, dan adjusted status.
  • Cetak laporan opname: Laporan lengkap dengan kolom sistem, fisik, selisih, dan status adjust.
  • Auto-generate opname number: Format SO-YYYYMMDD-###

13. Modul Tracking Batch/Lot

Modul untuk melacak obat dengan batch number berbeda secara terpisah. Penting kalau ada recall dari BPOM.

Fitur

  • Catat batch: Nomor batch dari pabrik, jumlah, tanggal masuk, tanggal kadaluarsa, nama pabrik farmasi.
  • Multiple batch per obat: Satu obat bisa punya multiple batch dengan tanggal kadaluarsa berbeda — masing-masing dilacak terpisah.
  • Recall BPOM: Tombol khusus untuk menandai batch sebagai "Ditarik (Recall)" dengan konfirmasi. Batch yang ditarik tidak boleh dijual.
  • Status batch: active, recalled, expired, depleted.
  • Peringatan kadaluarsa otomatis: Warna dan label berubah sesuai urgency: Merah (≤30 hari), Amber (≤90 hari), Biru (≤180 hari), Hijau (>180 hari)
  • Filter ganda: Berdasarkan status (aktif/recalled/expired/habis) dan urgency expiry.
  • Search: Cari berdasarkan nomor batch, nama obat, kode, atau pabrik.
  • Cetak laporan batch: Laporan lengkap semua batch dengan status expiry dan status batch.

17. Modul Perbaikan & Validasi (Quality/CAPA)

Modul untuk Corrective and Preventive Action (CAPA), incident tracking, dan logical testing. Khusus untuk Owner.

Fitur

  • Incident tracking: Catat insiden dengan severity (low/medium/high/critical) dan status (open/investigating/resolved/closed).
  • Countermeasure (CAPA): Tindakan korektif dan preventif dengan kategori (immediate/preventive), action type (SOP/visual/poka-yoke/audit/SWCS/other), effort level, dan impact level.
  • Logical testing: Uji logika IF-THEN, causation, MECE, dan sanity check.
  • Priority matrix: Matriks 2x2 untuk prioritisasi berdasarkan effort vs impact.
  • Trigger linkage: Countermeasures dapat di-link ke incidents secara otomatis.

20. Sistem Keamanan & RLS Policies

Row Level Security (RLS) diaktifkan pada setiap tabel di database. Setiap tabel memiliki 4 policy terpisah — satu per CRUD verb (SELECT, INSERT, UPDATE, DELETE). Tidak ada policy FOR ALL.

Policy Pattern

Aplikasi ini single-tenant dengan login internal untuk role management. Semua policy menggunakan TO anon, authenticated karena frontend berkomunikasi via anon key.

-- Pattern per tabel (4 policies)
DROP POLICY IF EXISTS "xxx_select" ON table_name;
CREATE POLICY "xxx_select" ON table_name
  FOR SELECT TO anon, authenticated USING (true);

DROP POLICY IF EXISTS "xxx_insert" ON table_name;
CREATE POLICY "xxx_insert" ON table_name
  FOR INSERT TO anon, authenticated WITH CHECK (true);

DROP POLICY IF EXISTS "xxx_update" ON table_name;
CREATE POLICY "xxx_update" ON table_name
  FOR UPDATE TO anon, authenticated USING (true) WITH CHECK (true);

DROP POLICY IF EXISTS "xxx_delete" ON table_name;
CREATE POLICY "xxx_delete" ON table_name
  FOR DELETE TO anon, authenticated USING (true);

Auth Security

  • Password disimpan sebagai bcrypt hash di tabel app_users
  • Login diverifikasi via Supabase Edge Function (verify-login) — password tidak pernah terlihat di client
  • Session disimpan di AuthContext (React Context) — tidak ada token JWT yang persist
  • persistSession: false di Supabase client config — tidak ada session yang disimpan di localStorage

Database Security Rules

  • Tidak ada DROP column, DELETE column, atau rename tabel yang bisa kehilangan data
  • Tidak ada BEGIN/COMMIT/ROLLBACK — DO $$ ... END $$ blocks diizinkan
  • Setiap migrasi idempotent (IF NOT EXISTS, DROP POLICY IF EXISTS sebelum CREATE)
  • Foreign keys dengan ON DELETE CASCADE atau ON DELETE SET NULL sesuai konteks
